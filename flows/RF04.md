# Fluxos funcionais do RF04 — Gerenciamento do carrinho

Este arquivo descreve o comportamento funcional das rotas de carrinho independentemente da arquitetura utilizada. Os projetos podem distribuir as responsabilidades entre rotas, controllers, models, use cases ou repositories de maneiras diferentes, mas devem preservar a mesma ordem de validação, o mesmo fluxo de dados, as mesmas exceções e as mesmas respostas HTTP.

## Comportamento comum

Todas as rotas de carrinho seguem inicialmente este fluxo:

1. Receber a requisição HTTP.
2. Validar o header `x-api-key` comparando-o com a variável de ambiente `X_API_KEY`.
3. Se o header estiver ausente ou tiver um valor diferente:
   - gerar `ForbiddenError`;
   - retornar HTTP `403` com `error`, `message` e `statusCode`;
   - interromper o fluxo antes de executar consultas ou alterações.
4. Se a autenticação for válida, continuar o fluxo específico da rota.

A representação de carrinho retornada pelas rotas possui o seguinte formato:

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "createdAt": "2026-01-15T12:00:00.000Z",
  "items": [
    {
      "id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
      "productId": "0f5ead3a-8c1e-4b2a-9d4c-1a2b3c4d5e6f",
      "quantity": 2
    }
  ]
}
```

`createdAt` é representado em ISO-8601 UTC e `items` é sempre um array.

## `POST /cart`

Cria um carrinho vazio.

### Entrada

- A rota não exige parâmetros de path ou query.
- O body é vazio ou ignorado.

### Fluxo

1. Gerar um novo identificador para o carrinho.
2. Definir a data e hora de criação.
3. Criar o carrinho com a lista de itens vazia.
4. Persistir o novo carrinho.
5. Transformar o carrinho para a representação HTTP.
6. Retornar HTTP `201` com `items: []`.

### Fluxo de sucesso

```text
requisição autenticada
  → geração do identificador e da data
  → criação do carrinho vazio
  → persistência
  → representação HTTP
  → resposta 201
```

### Validações e exceções

- Além da autenticação comum, não há validação de entrada.
- A operação não gera exceção semântica de carrinho.

## `GET /cart/{cartId}`

Consulta um carrinho e seus itens.

### Fluxo

1. Obter `cartId` a partir do path da requisição.
2. Consultar o carrinho persistido cujo identificador seja igual a `cartId`.
3. Se o carrinho não existir:
   - gerar `CartNotFoundError` com o identificador recebido;
   - retornar HTTP `404` com `error`, `message` e `statusCode`.
4. Se o carrinho existir, consultar todos os itens associados a ele.
5. Associar os itens encontrados ao carrinho.
6. Transformar o carrinho e seus itens para a representação HTTP.
7. Retornar HTTP `200` com o carrinho.
8. Se o carrinho não possuir itens, retornar `items: []`.

### Fluxo de sucesso

```text
cartId do path
  → consulta do carrinho
  → consulta dos itens
  → montagem do carrinho completo
  → representação HTTP
  → resposta 200
```

### Fluxo de exceção

```text
carrinho não encontrado
  → CartNotFoundError
  → resposta 404
```

## `POST /cart/items`

Adiciona um produto ao carrinho. Se o produto já estiver no carrinho, incrementa a quantidade do item existente.

### Entrada

```json
{
  "cartId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "productId": "0f5ead3a-8c1e-4b2a-9d4c-1a2b3c4d5e6f",
  "quantity": 2
}
```

### Fluxo

1. Obter `cartId`, `productId` e `quantity` a partir do body.
2. Validar `quantity` antes de executar qualquer consulta.
3. A quantidade é válida somente quando for um número inteiro maior que zero.
4. Se `quantity` estiver ausente, for não numérica, fracionária, igual a zero ou negativa:
   - gerar `InvalidQuantityError` com o valor recebido;
   - retornar HTTP `400` com `error`, `message` e `statusCode`;
   - não consultar nem alterar o produto ou o carrinho.
5. Consultar o produto correspondente a `productId`.
6. Se o produto não existir:
   - gerar `ProductNotFoundError` com o identificador recebido;
   - retornar HTTP `404` com `error`, `message` e `statusCode`.
7. Consultar o carrinho correspondente a `cartId`.
8. Se o carrinho não existir:
   - gerar `CartNotFoundError` com o identificador recebido;
   - retornar HTTP `404` com `error`, `message` e `statusCode`.
9. Consultar se já existe no carrinho um item associado ao produto.
10. Calcular a quantidade final:
    - item existente: `quantidadeFinal = quantidadeAtual + quantity`;
    - item inexistente: `quantidadeFinal = quantity`.
11. Comparar a quantidade final com o estoque do produto.
12. Se a quantidade final for maior que o estoque disponível:
    - gerar `InsufficientStockError`;
    - retornar HTTP `409` com `error`, `message` e `statusCode`;
    - não criar nem atualizar o item.
13. Se o item já existir, substituir sua quantidade pela quantidade final e persistir a alteração.
14. Se o item não existir, gerar um identificador e persistir um novo item com `cartId`, `productId` e `quantity`.
15. Consultar novamente o carrinho com seus itens atualizados.
16. Transformar o carrinho para a representação HTTP.
17. Retornar HTTP `201` com o carrinho atualizado.

### Regras da operação

- Adicionar um item ao carrinho não decrementa o estoque do produto.
- A verificação de estoque considera a quantidade que já existe no carrinho.
- Um mesmo produto aparece no máximo uma vez no carrinho; novas adições incrementam o item existente.

### Fluxo de sucesso

```text
cartId + productId + quantity
  → validação da quantity
  → consulta do produto
  → consulta do carrinho
  → consulta do item
  → cálculo da quantidade final
  → validação do estoque
  → criação ou atualização do item
  → consulta do carrinho atualizado
  → resposta 201
```

### Fluxos de exceção

```text
quantity inválida
  → InvalidQuantityError
  → resposta 400
```

```text
quantity válida + produto não encontrado
  → ProductNotFoundError
  → resposta 404
```

```text
produto encontrado + carrinho não encontrado
  → CartNotFoundError
  → resposta 404
```

```text
quantidade final maior que o estoque
  → InsufficientStockError
  → resposta 409
```

## `DELETE /cart/items/{productId}`

Remove de um carrinho o item associado ao produto informado.

### Entrada

- `productId`: recebido pelo path.
- `cartId`: recebido obrigatoriamente pela query string.

Exemplo:

```text
DELETE /cart/items/0f5ead3a-8c1e-4b2a-9d4c-1a2b3c4d5e6f?cartId=3fa85f64-5717-4562-b3fc-2c963f66afa6
```

### Fluxo

1. Obter `productId` a partir do path.
2. Obter `cartId` a partir da query string.
3. Consultar o carrinho correspondente a `cartId`.
4. Se o carrinho não existir, inclusive quando `cartId` estiver ausente ou não corresponder a um carrinho persistido:
   - gerar `CartNotFoundError` com o valor recebido;
   - retornar HTTP `404` com `error`, `message` e `statusCode`.
5. Consultar no carrinho o item associado a `productId`.
6. Se o item não existir:
   - gerar `CartItemNotFoundError` com o identificador do produto;
   - retornar HTTP `404` com `error`, `message` e `statusCode`.
7. Remover o item persistido.
8. Consultar novamente o carrinho com seus itens restantes.
9. Transformar o carrinho atualizado para a representação HTTP.
10. Retornar HTTP `200` com o carrinho sem o item removido.

### Regra da operação

A remoção do item não altera o estoque do produto.

### Fluxo de sucesso

```text
productId do path + cartId da query
  → consulta do carrinho
  → consulta do item
  → remoção do item
  → consulta do carrinho atualizado
  → resposta 200
```

### Fluxos de exceção

```text
carrinho não encontrado
  → CartNotFoundError
  → resposta 404
```

```text
carrinho encontrado + item não encontrado
  → CartItemNotFoundError
  → resposta 404
```

# Fluxos funcionais do RF02 — Busca e filtragem de produtos

O sistema deve permitir busca e filtragem de produtos.

Este arquivo descreve o comportamento de `GET /products` independentemente da arquitetura. Somente produtos não deletados entram na listagem. Estoque não é alterado por esta rota.

## Comportamento comum

1. Receber a requisição HTTP.
2. Validar o header `x-api-key` contra `X_API_KEY`.
3. Se ausente ou diferente: `ForbiddenError`, HTTP 403.
4. Seguir o fluxo da rota.

Representação HTTP de cada item:

```json
{
  "id": "0f5ead3a-8c1e-4b2a-9d4c-1a2b3c4d5e6f",
  "name": "Produto",
  "slug": "produto",
  "description": "",
  "price": 100,
  "stock": 0
}
```

## `GET /products`

Lista produtos não deletados, ordenados por `id`. Filtros opcionais na query:

- `name` — contém, case-insensitive
- `minPrice` / `maxPrice` — números ≥ 0; `minPrice > maxPrice` é inválido
- `available=true|false` — `true` lista `stock > 0`; `false` lista `stock = 0`

### Fluxo

1. Obter os filtros opcionais da query.
2. Validar `minPrice` e `maxPrice` quando presentes: devem ser números ≥ 0; se ambos existirem, `minPrice` não pode ser maior que `maxPrice`.
3. Validar `available` quando presente: somente `true` ou `false`.
4. Consultar produtos com `deleted_at` nulo, aplicando os filtros válidos.
5. Ordenar pelo identificador.
6. Transformar cada produto para a representação HTTP.
7. Retornar HTTP 200 com o array (vazio permitido).

### Exceções

- `InvalidPriceError` 400
- `InvalidFilterError` 400

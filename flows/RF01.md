# Fluxos funcionais do RF01 — Cadastro de produtos

O sistema deve permitir criar, consultar, atualizar e excluir produtos do catálogo.

Este arquivo descreve o comportamento das rotas de cadastro independentemente da arquitetura. Estoque não é alterado por estas rotas: o produto nasce com `stock = 0` e a quantidade é gerida em `/stocks`. Delete é sempre soft delete (`deleted_at`). Produto deletado não aparece em listagens e é tratado como inexistente (`ProductNotFoundError`). Itens de carrinho cujo produto foi deletado permanecem no banco, mas não são devolvidos nas leituras do carrinho.

## Comportamento comum

1. Receber a requisição HTTP.
2. Validar o header `x-api-key` contra `X_API_KEY`.
3. Se ausente ou diferente: `ForbiddenError`, HTTP 403.
4. Seguir o fluxo da rota.

Representação HTTP:

```json
{
  "id": "0f5ead3a-8c1e-4b2a-9d4c-1a2b3c4d5e6f",
  "name": "Produto",
  "description": "",
  "price": 100,
  "stock": 0
}
```

## `GET /products/{productId}`

Consulta um produto ativo. Inexistente ou deletado: `ProductNotFoundError` 404. Sucesso: 200.

## `POST /products`

Body: `name` (string não vazia), `price` (número ≥ 0), `description` opcional (default `""`). Persistir com `stock = 0`. Sucesso: 201.

Exceções: `InvalidNameError` 400; `InvalidPriceError` 400.

## `PUT /products/{productId}`

Substitui `name`, `description` e `price`. Não altera `stock`. Inexistente ou deletado: 404. Validação igual ao create.

## `DELETE /products/{productId}`

Preenche `deleted_at`. Não apaga `cart_items`. Sucesso: 200 com o payload do produto. Já deletado ou inexistente: 404.
